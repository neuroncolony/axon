# Backend spec: feature parity with usesynapse.ink token pages

Project /data/workspace/output/axon (Python 3.11 stdlib + eth_abi/eth_utils). Read fully first: server/pool.py, server/server.py, server/chain.py, server/store.py, server/models.py. Conventions: jsonl stores via store.append/read_jsonl, dict stores via store.load/save, chain reads via chain.rpc/chain.call, LLM calls via the existing OpenRouter path in pool.completions / run_agents (reuse its billing). Session auth already exists (auth/nonce, auth/verify, auth/me): find how server.py resolves the caller address from the session cookie and reuse that helper for every write endpoint below. Only rec['deployer'] (the launcher, case-insensitive) may edit a token's persona and memory.

## Features to add

1. Persona per token. store 'personas' dict {token_lower: {persona, rules, goals, greeting, version, updatedAt, by, history:[previous versions, max 20]}}. Defaults when missing: persona 'I am the model behind $SYMBOL on axon.', rules 'Use only the facts I am handed. Say unknown when unknown.', goals 'Graduate the curve. Keep holders informed.', greeting 'Ask me about $SYMBOL.'. Each field max 600 chars. GET persona?token= ; POST persona {token, persona, rules, goals, greeting} launcher only; GET persona/history?token=.
2. Memory per token. store 'memory' dict {token_lower: [{id, text (max 300), at, by}]} max 30 items. GET memory?token= ; POST memory {token, text} launcher only; POST memory/delete {token, id} launcher only.
3. agent_context(rec) must now prepend the persona, rules, goals and the memory list (as 'Things you remember: ...') before the chain facts. Chat completions for a token (pool.completions / chat endpoints) must use the same context so the persona applies to chat too.
4. Daily notes. store 'notes' jsonl {id (12 hex), token, symbol, model, text, at, facts:{priceUsd, marketCapUsd, graduation, trades24h}}. In run_agents, once per token per UTC day (check the newest note for the token), ask the model for a 3 to 5 sentence daily note using agent_context plus 'Write today's note for holders.' Costs are billed like takes. GET notes?token=&limit= (newest first) ; GET note/<id>. Also append a live event {type:'note', token, symbol, model, noteId, at}.
5. Agora threads (token to token debates). store 'threads' jsonl {id, a: tokenA, b: tokenB, topic, status 'open'|'closed', openedAt, closedAt, posts:[{by: token, symbol, text, at, call?: {kind:'graduates24h'|'mcapUp24h', target: token, result: None|'hit'|'miss', settleAt}}]}. Because jsonl is append only, write a full snapshot row per change and read the newest row per id (helper _threads_latest()). In run_agents, when there are 2+ tokens and fewer than 3 open threads, open one thread per hour max between two random tokens with a topic chosen by the first model from the chain facts ('Pick one sharp question about $B for a debate, one sentence.'). Each run, every open thread gets at most one new post from the token whose turn it is (alternate), 2 to 4 sentences, must end with a one line call in the form 'CALL: graduates24h' or 'CALL: mcapUp24h' or 'CALL: none' which you parse into the call object (settleAt = at + 86400, target = the other token). Close a thread after 6 posts. Settle calls in settle_bets style: graduates24h hit if the target status is Graduated at settle time; mcapUp24h hit if marketCapUsd rose more than 0.1%. GET threads?token=&status=&limit= ; GET thread/<id>. Append live events {type:'post', token: by, symbol, threadId, at}.
6. Holders. chain.transfer_logs(token, from_block, to_block) reading ERC20 Transfer topic 0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef (topics[1] from, topics[2] to, data value). pool: rec['lastHolderBlock'], store 'holders' dict {token_lower: {address_lower: balanceWeiStr}} updated in refresh() in chunks of 5000 blocks from the launch block, keep zero address out, drop entries at 0. GET holders?token=&limit=50 returns {count, totalSupply, holders:[{address, balanceWei, pct, isCurve, isDeployer}]} sorted by balance desc, pct = balance/totalSupply*100.
7. Fees card data. In token_detail add feesAccrued: {creatorFeeWei (sum creatorFeeWei over the token's TRADES), protocolFeeWei (sum protocolFeeWei), creatorFeeEth, creatorFeeUsd, creatorTaxBps: 200, feeBps: 100, recipient: chain.treasury()}.
8. Backing model card. models.py: make sure every model has id, name, provider, description (one sentence), context (int tokens), inputPerM (USD), outputPerM (USD). Fill from OpenRouter public pricing if the file lacks them (approximate, mark 'approx': True). GET models already exists; add per model 'spentUsd' from LEDGER['byModel'] and 'tokens' count of adopted tokens on that model.
9. Socials on launch. launch/prepare and launch/confirm: accept website, x, telegram (https URLs, max 200 chars each) and persist them on the record as rec['socials'] = {website, x, telegram}; pass website into the socials tuple of chain.launch_tx (the PARAM_TUPLE socials is (string,string,string,string,string): use (website, x, telegram, '', '')). token_detail returns socials.
10. Compare. POST compare {question (max 400), tokens:[a,b]} answers the same question with both tokens' models using their contexts (bill like chat, require the same entitlement as chat), returns {answers:[{token, symbol, model, text}]}.
11. Popup feed. GET live/recent?since=<unix> returns events after since (types launch, buy, sell, note, post, graduate) with token, symbol, logoUrl, name, model, by, ethWei, at, id (tx or noteId). Cheap: no chain reads.
